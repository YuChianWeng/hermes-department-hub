# M1 routing, ownership, delivery, privacy review

Scope: source read only, no board writes, no production/live execution. All reproduction data and effects below are synthetic in `probe.py`, which imports the reviewed source and uses isolated SQLite databases/fake board/effect ports. Source directory is not a Git repository. The installed Hermes source inspected for API semantics is commit `f0d94882e89ab8d4098b5bb2f166adfb9ee0a0ab`; not a new live-gateway test. Known subscription inheritance and shared-board metadata exposure are excluded as pre-existing P0 limitations.

## Findings

1. **P1 — manager wake owner is wrong or unchecked.** `department_lib/kanban_cli.py:132–138` omits supported `--notifier-profile`; CLI defaults to its active profile (`hermes_cli/kanban.py:1155–1173`). `routing.py:49–52, 56–79` checks only platform/chat/mode and never the persisted `notifier_profile`. Synthetic new and pre-existing rows with owner `default`, expected `dev-manager`, were both reported routing OK. Installed official docs `website/docs/user-guide/features/kanban.md:1297–1333` require profile-owned delivery; prior P0-R negative owner/session evidence shows a mismatch remains undelivered. That historical isolated live evidence is not a new live M1 test. Fix: set and verify owner as well as complete target routing anchors; don't assume subscribe-time target validation.

2. **P1 — cross-department target can be subscribed before its owner is locally cached; bound ownership then becomes stale.** `orchestrator.py:68–74, 245–250` passes local store bindings only; `routing.py:87–94` permits unknown owners without checking board ancestry. Synthetic `ops-child -> ops-root` with no stored child binding was subscribed to dev manager and returned OK. `_resolve_dept` (`orchestrator.py:78–92`) also permanently trusts a previous cached owner: synthetic `late-child` initially under dev, then moved under ops, is still ingested as dev. Validate current topology or require explicit authoritative ownership and handle conflicts/moves fail-closed; merely finding a local task row is not current board verification.

3. **P1 — concurrent final calls duplicate the effect despite the promised at-most-one guarantee.** `delivery.py:115–118` performs `get_delivery` then `put_delivery` then unconditionally `_apply`; `store.py:478–489` uses `INSERT OR IGNORE` without returning whether caller won. Two independent SQLite connections synchronized after their empty read both returned `delivered` and the synthetic port recorded two appends. This is distinct from the README's explicit non-guarantee of external *exactly*-once: it violates its affirmative at-most-one-effective-final claim. Atomically claim/serialize sends and address crash-in-flight ambiguity before retry.

4. **P1 — failed or detached ancestry still sends to an arbitrary department root.** `orchestrator.py:224–243` silently falls back to the first stored department root both on `BoardError` and when no matching ancestor exists. Synthetic disconnected task and unreadable ancestry each selected `dev-root`; escalation was sent there. With multiple department roots this can send a report to another work tree/coordinator. Treat unknown/no root/ambiguous roots as held; don't append until exact target is established.

5. **P1/P2 — escalation passes secrets and transcripts through verbatim.** Tool description `__init__.py:101–112` promises no credentials or transcript, but `_handle_escalate` only checks `dict` at `:251–259`, and `delivery.py:167–175` serializes all detail into a root-card comment. Synthetic token and transcript appeared unchanged in the effect. This is direct explicit-publication behavior, not a claim that the shared board is an ACL. Use a small allowlist/typed public reason data or reject unsafe input rather than claiming general sanitization.

6. **P2 — unknown final deliveries have no registered reconciliation tool.** `delivery.py:123–158` intentionally never retries unknown from normal release and supplies `reconcile` for an authoritative-absent retry, but `__init__.py:20–27, 264–270` registers no reconcile handler. Synthetic effect failed before writing; a second release stayed `unknown` with `find=absent` and one append attempt. The operator cannot recover through the advertised plugin tools; invoking the raw library directly is outside the registered interface and also needs fresh acceptance/gate validation before a resend.

7. **P2 — incomplete comment rows falsely prove absent.** `kanban_effects.py:68–85` skips a comment object missing a body (or a non-object), then returns `absent`; a synthetic malformed row reproduced this. Reconcile may resend on that answer. Installed CLI `show --json` emits body for normal stored comments, so this demonstrates an incomplete/malformed-provider fail-closed gap, not a claim that ordinary current CLI output omits bodies.

Additional observation: ingest binds a newly discovered child but never ensures its subscription (`orchestrator.py:78–138`); if the child existed before a root subscription and was not passed in `task_ids`, discovery alone does not repair routing. Inheritance may cover later create/link events, subject to the known P0 limitation.
